# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

LunaTranscribe is a macOS menu-bar dictation app (Swift/SwiftUI, macOS 15+, Apple Silicon only). Hotkey → record → local CoreML transcription (FluidAudio: Parakeet TDT v3 or Cohere Transcribe) → text pasted into the frontmost app. A third hotkey adds **LLM post-processing** (`Refine/`: LFM2/Qwen3 via MLX, or Apple Foundation Models) that cleans grammar, fillers and repetitions before pasting. A user-maintained **custom vocabulary** (`Vocabulary/`) fixes names and jargon in both. A separate **meeting mode** records mic + system audio to a WAV, then diarizes (pyannote via FluidAudio) and transcribes per speaker turn; results live as JSON in a **meeting library** in a user-chosen folder and can be summarized on demand via the **Claude CLI**. The dictionary **learns from corrections** made in the app (suggestions the user confirms). A **main window** (overview, meetings, dictionary, history, settings) opens from the menu bar; the app stays `LSUIElement`. Fully offline except the one-time model downloads and the opt-in Claude summary. MIT-licensed open source; `docs/Vergleich-LunaTranscribe-vs-WisprFlow.md` compares it with Wispr Flow and documents the local-first architecture. Details for users (permissions, first start, privacy) are in `README.md`.

**Language:** code comments, log messages, UI strings and the README are German. Keep new comments and user-facing strings German; identifiers stay English.

## Build & run

The Xcode project is **generated from `project.yml` with XcodeGen** and is gitignored (`*.xcodeproj`). Edit `project.yml`, never the `.pbxproj`, and regenerate after changes:

```bash
xcodegen generate
```

Debug build from the CLI (Xcode: open `LunaTranscribe.xcodeproj`, ⌘R):

```bash
xcodebuild -project LunaTranscribe.xcodeproj -scheme LunaTranscribe -configuration Debug -destination 'platform=macOS,arch=arm64' -derivedDataPath build/debug build 2>&1 | grep -E "error:|warning: .*LunaTranscribe/LunaTranscribe/|BUILD"
```

Release build, sign, install to `/Applications`, and launch (the everyday path; the scheme's Run config is Release because FluidAudio is much slower in Debug):

```bash
./scripts/build-release.sh
```

Code signing comes from `Config/Signing.xcconfig` (ad-hoc by default, so anyone can build) which `#include?`s the gitignored `Config/Local.xcconfig` holding the maintainer's `DEVELOPMENT_TEAM` (template: `Local.xcconfig.example`). A stable team keeps TCC permissions (mic, accessibility, system audio) across rebuilds; never put a team ID back into `project.yml` (target settings would override the xcconfig). There is no App Sandbox (needed for global hotkeys + ⌘V injection) and hardened runtime is on.

Building needs the **Metal Toolchain** (separate Xcode component since Xcode 26; `xcodebuild -downloadComponent MetalToolchain`) because mlx-swift compiles its GPU kernels. The first build after a clean takes several minutes for that. `FoundationModels` is weak-linked (`OTHER_LDFLAGS` in `project.yml`) so the macOS 15 deployment target still launches; every use of that framework sits behind `#available(macOS 26, *)`.

**There are no unit tests.** The only automated check is the meeting-pipeline self-test, which records N seconds of mic + system audio, processes it, and writes channel levels + transcript to a log, then exits. It must be launched via `open` (not directly from a terminal), otherwise TCC attributes the system-audio permission to the terminal and the tap records silence:

```bash
open -n /Applications/LunaTranscribe.app --args --meeting-selftest 20 --log /tmp/luna-selftest.log
```

Play something (e.g. `say -v Anna "…"`) while it runs. Implemented in `Meeting/MeetingSelfTest.swift`, triggered from `LunaTranscribeApp.init`.

The refine pipeline has its own self-test that needs no audio permission, so it can run straight from the terminal (first run downloads the model). Use it to iterate on `RefinePrompt`; it prints one cold and two warm passes with timings:

```bash
./build/debug/Build/Products/Debug/LunaTranscribe.app/Contents/MacOS/LunaTranscribe --refine-selftest "ähm also ich wollte sagen dass dass wir morgen um elf uhr das meeting haben" --model qwen3_1_7b --language de
```

The vocabulary self-test also needs no permission. It transcribes audio files with Parakeet three times (no vocabulary, acoustic boosting only, boosting + aliases) and prints texts and timings. Create input with `say -v Anna -o x.wav --data-format=LEF32@16000 "…"`:

```bash
./build/debug/Build/Products/Debug/LunaTranscribe.app/Contents/MacOS/LunaTranscribe --vocab-selftest x.wav [more.wav …] --terms "LunaTranscribe=Luna Transcribe,Luna transkribe;Kubernetes" --language de
```

Three more self-tests need no permission: `--learn-selftest` (built-in correction cases for the learning dictionary, or `"before" "after"` for one case), `--summary-selftest [meeting.json] [--model x] [--cli path]` (Claude CLI summary through the app's code path — sends text to Anthropic), and `--queue-selftest <wav…>` (enqueues each file as a finished meeting, waits for the queue, prints order/timings/results; temp library, setting restored), and `--ui-snapshot <dir>` (renders every main-window page, two settings sections and the menu popover in light and dark mode as PNGs, with a sample meeting in a temp folder; the real meeting folder setting is restored). Use `--ui-snapshot` to check design changes — computer-use can't see the `LSUIElement` app.

While any self-test runs, `AppState(preloadModels: false)` skips loading models so two downloads don't race on the same file.

Logs go through `Log.<category>` (`App/Log.swift`: `timing`, `meeting`, `systemaudio`, `refine`, `vocabulary`, `summary`), subsystem `com.maximhofmeister.LunaTranscribe`; read with `log stream --predicate 'subsystem == "com.maximhofmeister.LunaTranscribe"'`.

The app icon is drawn in code: `swift scripts/make-icon.swift` regenerates `Resources/Assets.xcassets/AppIcon.appiconset` (`--preview <png>` for one 1024 px image). `scripts/build-mediaremote-adapter.sh` rebuilds the vendored `Vendor/MediaRemoteAdapter` framework from upstream (needs cmake); only needed when bumping that dependency.

## Architecture

Two independent state machines share one loaded model:

- **`AppState`** (`App/`, `@MainActor ObservableObject`) — the root that owns and wires everything: `ModelManager`, `RefinerManager`, `DictationController`, `MeetingSession`, `MeetingStore`, `MeetingSummarizer`, `VocabularyLearner`, `MainRouter` + `MainWindowController`, `OverlayController`, `EscapeKeyMonitor`, hotkey registration and the accessibility poll. It re-publishes its children's `objectWillChange` (`forwardChanges(of:)`) so the menu bar and main window only observe `AppState`. `openMainWindow(_:)`, `openSettings(_:)`, `openMeeting(_:)` drive navigation.
- **`DictationController`** (`App/`) — dictation state machine. Owns `AudioRecorder` (memory sink), `MediaPlaybackController`, the RAM-only history (max 20). Flow: `KeyboardShortcuts` hotkey (`Hotkey/Shortcuts.swift`; each `HotkeySlot` maps to a `DictationRequest` = language + `refine` flag; `.refined` uses the primary language) → `start` → `stopAndTranscribe` → `engine.transcribe(samples, language:)` → optional `refine` (status `.refining`, overlay „Formuliere…") → `TextInjector.insert` (pasteboard + synthetic ⌘V, requires Accessibility). A `generation` counter discards late results after Escape/cancel, checked again after refining. `Transcript.rawText` keeps the pre-refine text. The overview's "words/dictations today" come from `SettingsStore.dailyDictationStats` (`DailyDictationStats`: day key + two counts, no text), bumped on every insert — deliberately independent of the RAM history, which is capped at 20, lost on restart and may be switched off.
- **`MeetingSession`** (`Meeting/`) — meeting **recording only** (`idle`/`recording`/`failed`). Own `AudioRecorder` (file sink → WAV in `~/Library/Caches/LunaTranscribe/Meetings`) and `SystemAudioTap`; needs no loaded model. `stop()` hands the WAV to `MeetingProcessingQueue.enqueue` and is immediately idle again, so the next meeting can start right away.
- **`MeetingProcessingQueue`** (`Meeting/`) — background processing, strictly **one job at a time** (diarizer + engine would otherwise fight over the ANE/RAM and both finish later). Each job is `AppPaths.meetingQueue/<id>/audio.wav` + `job.json` (`MeetingJob`: recordedAt, duration, language and speaker count frozen at stop time, `failure`). Jobs survive quits: `restore()` re-reads them at launch; a job that was running is simply waiting again. It starts jobs when the engine becomes ready (observes `models.$state`), owns the long-lived `SpeakerDiarizer`, runs `MeetingTranscriber.run` on a detached task, then `MeetingStore.add` (WAV moves along if „keep audio") and deletes the job folder only after a successful save. Failures keep the audio (`retry`/`discard`). It publishes `finished`/`failed`; `AppState` turns those into `MeetingNotifier` notifications (asked for permission on the first queued meeting; clicking opens the meeting) — deliberately **no window pops up**, it would interrupt the next meeting. Invariant: **a recording is never lost** until it's saved or the user discards it. `--queue-selftest <wav…>` exercises the real queue with a temp library (cleanup must run before `exit` — `exit` skips `defer`, hence `runIsolated`). Escape deliberately does **not** cancel a meeting; only the menu does. Dictation keeps working during a meeting and lands in the meeting audio too.

**Meeting library** (`Meeting/MeetingStore`, `MeetingDocument`, `LegacyMeetingImporter`): one folder per meeting in `SettingsStore.meetingFolder` (UserDefaults key is still the historical `meetingExportFolder`; default `~/Documents/LunaTranscribe Meetings`, **deliberately not** Application Support — the user wants it browsable and choosable). Folder `<yyyy-MM-dd HH-mm> <title> · <6-char id>` holds `meeting.json` (`MeetingTranscript` is `Codable`, `schemaVersion`, ISO-8601 dates, atomic writes — the source of truth), `summary.md` (mirrors `summary`) and optionally `audio.wav`. Renaming the title renames the folder. Invariant: **a transcript is never lost** — if the folder can't be created (`folderIssue`), `add` writes to `AppPaths.unsavedMeetings` and `reload` moves those into the library once it's reachable. `reload` also imports v0.1 `Meeting *.txt` backups once (`importedFrom` prevents repeats; originals untouched). Changing the folder in Settings asks whether to move existing meetings (`moveMeetings(from:)`). TXT/MD are export-only (`MeetingExporter`). `MeetingDocument` is the open meeting: edits autosave after 0.5 s, turn corrections feed `VocabularyLearner`, and it adopts summaries from `MeetingSummarizer.completed` so a pending save doesn't drop them.

**Summaries** (`Summary/`): `ClaudeCLI` locates `claude` (setting → `~/.local/bin`, `~/.claude/local`, Homebrew, `/usr/local/bin` → login-shell `command -v`; GUI apps don't inherit the shell PATH) and runs `claude -p --tools "" --strict-mcp-config --setting-sources "" --no-session-persistence --disable-slash-commands --output-format text --system-prompt <prompt> [--model m]` in an empty temp dir with the transcript on stdin, pipes read continuously, 5 min timeout, cancellable. It sets `USER`/`LOGNAME` if missing — without them the CLI can't find its keychain login ("Not logged in"). `MeetingSummarizer` runs at most once per meeting, re-reads the meeting from disk on completion, stores the summary itself (even if the meeting isn't open) and emits `completed`. `SummaryPrompt` mirrors `RefinePrompt` (German default, `{language}` → German language name, only non-default text persisted). This is the app's only cloud path: first use shows a one-time notice (`summaryCloudNoticeAccepted`), the button has a cloud hint.

**Refine pipeline** (`Refine/`): mirrors `Engine/` deliberately — `TextRefiner` protocol + `RefinerKind` enum + `RefinerManager` (same shape as `ModelManager`, kept separate instead of a generic manager). Backends: `MLXRefiner` (LFM2 1.2B default, Qwen3 1.7B, Qwen3 4B; `LLMModelFactory.loadContainer` with `HubApi(downloadBase: ModelPaths.base)`, greedy, `enable_thinking: false`, `maxTokens` derived from input length, 20 s timeout) and `AppleIntelligenceRefiner` (`@available(macOS 26, *)`, new `LanguageModelSession` per call). `RefinerKind.availability` asks `SystemLanguageModel.default.availability` and is what greys out the Apple option in Settings. `RefinePrompt` is the backend-neutral part: `defaultTemplate` (English system prompt with a `{language}` placeholder; the user can edit it in Settings, stored in `SettingsStore.refinePrompt` only when it differs from the default), the dictation wrapped in `<dictation>` tags (stops small models answering questions in the text), few-shot `examples` sent as real user/assistant turns (as prose in the system prompt, 1B models copy the example format), and `sanitize` which strips tags/preambles/quotes and rejects outputs outside 0.4–2× the input length. Iterate on prompts with `--refine-selftest … --prompt <file>` instead of rebuilding. Known limit (tested 2026-09-21 on all three MLX models with several prompt variants): a whole repeated-and-corrected sentence („Heute ist … nein, morgen ist …") is not resolved; in-sentence corrections („Montag nein Dienstag") work from Qwen3 4B up. Adding more rules about it made results worse — don't spend more time there without a bigger model. **Invariant: a dictation is never lost** — `AppState.refine` returns the raw transcript plus a notice on any failure (model still loading, error, timeout, implausible output) and the caller pastes that.

**Engines** (`Engine/`): `TranscriptionEngine` protocol (`prepare(progress:)`, `transcribe(_:language:)`, `configureVocabulary(_:)`, `unload()`) with `ParakeetEngine` and `CohereEngine` wrapping FluidAudio. `ModelManager` keeps exactly one engine loaded and swaps on `SettingsStore.engine` changes. Models live under `ModelPaths.base` (`~/Library/Application Support/LunaTranscribe/Models`), shared with the diarizer models. `AppLanguage` maps each language to the FluidAudio enums of both engines; `SettingsStore.languageForEngine` falls back to English when the chosen language is unsupported by the active engine.

**Custom vocabulary** (`Vocabulary/`, `SettingsStore.vocabularyEnabled` + `vocabularyEntries` as JSON in defaults): one list of `VocabularyEntry` (term + aliases) feeds two stages inside the engines, so dictation, meetings and self-tests all get it with no call-site changes. (1) `CustomVocabulary.correct` — one precompiled case-insensitive regex over all aliases (longest first, the term itself counts as an alias to fix casing), Unicode word boundaries via lookarounds; runs in every engine and again in `AppState` after refining so the LLM cannot undo a term. (2) Parakeet only: FluidAudio `VocabularyBoostingSession` with the separate CTC 110M model (English-only, ~100 MB, lives in FluidAudio's own cache dir because its tokenizer lookup is hardcoded there). Two deliberate deviations from FluidAudio defaults, both found with `--vocab-selftest`: `spotterRescueEnabled: false` (the rescue turned „Das Wetter ist heute schön" into „weclapp weclapp"), and only the rescorer's *decisions* (`replacements`) are applied, via `CustomVocabulary`, because its rebuilt text drops punctuation next to replaced words. `ModelManager.updateVocabulary` pushes changes (debounced 0.6 s in `AppState`, serialized so an older session never overwrites a newer one) and publishes `vocabularyState` for Settings; a boosting failure leaves the alias stage running. Engines keep the vocabulary in `Mutex`es because meetings transcribe on a detached task. Cost: ~0.15 s per dictation (release, M3).

**Learning dictionary** (`Vocabulary/CorrectionLearner`, `VocabularyLearner`, `VocabularySuggestion`): corrections in the history page and in meeting turns go through `CorrectionLearner.candidates(before:after:)` — word-level LCS diff, replacement hunks of 1–3 words, rejected when less than half the words were kept (rewrite), stop words, sentence-start capitalisation, punctuation-only, lowercase inflections (`isInflection`), or spelling/phonetic similarity < 0.5; mid-sentence case changes count as brands. `VocabularyLearner` merges candidates into `SettingsStore.vocabularySuggestions` (counted, skipping ignored keys and variants the dictionary already fixes); `accept` adds a new entry or an alias to an existing term, `ignore` adds to `ignoredSuggestionKeys`. **Never auto-apply** — Maximilian's rule, a wrong replacement hits every future dictation. Extend `LearnSelfTest.cases` when touching the heuristics.

**Meeting pipeline** (`MeetingTranscriber`): diarizer segments → `buildTurns` (merge same-speaker segments with gaps ≤ 1 s, fold turns < 0.5 s into the predecessor) → slice each turn from the WAV with 0.15 s padding → `engine.transcribe` per turn → renumber speakers as „Sprecher 1…n" by first appearance. This **turn-slicing** design is intentional: it keeps the engine protocol unchanged and works with Cohere, which returns no word timestamps. Thresholds are constants at the top of `MeetingTranscriber`. `MeetingSpeakerCount` (0 = auto) is passed to the diarizer clustering because automatic clustering tends to collapse similar voices into one speaker.

**Audio capture** (`Audio/`): `AudioRecorder` produces 16 kHz mono Float32 from a `CaptureSource` (device + `channelGroups` for per-source mixing, e.g. `[[mic], [sysL, sysR]]`). System audio uses a Core Audio process tap plus a private aggregate device (output device as master/clock + mic + tap) read via a raw IOProc in `DeviceInputStream` — not `AVAudioEngine`, which drops the channel layout after device changes. `tapautostart` is intentionally off so a silent recording still produces a file. If the system-audio permission is denied, macOS silently delivers silence; `MeetingSession.captureSource` falls back to mic-only and sets `systemAudioActive = false` for the menu hint. Input/output devices are fixed at meeting start.

**Media pause** (`Output/MediaPlaybackController`): macOS ≥ 15.4 blocks MediaRemote for normal apps, so the vendored `MediaRemoteAdapter.framework` (embedded, not linked, code-signed) is loaded by `/usr/bin/perl` via `mediaremote-adapter.pl` (bundled as a resource). Only resumes playback it paused itself.

**Settings** (`Settings/SettingsStore`): singleton over `UserDefaults`; each `@Published` property persists in `didSet` via typed `Key`s and `save`/`load`/`saveJSON`/`saveUnlessDefault` helpers (key raw values are stored data — never rename). `launchAtLogin` is backed by `SMAppService`, not defaults. The UI is `Settings/Pages/` (one view per `SettingsSection`) shown inside the main window; there is no separate Settings scene.

**UI & design** (`UI/`): design system „Mondnacht" in `UI/Theme` — `LunaColor` (dynamic light/dark tokens), `LunaFont` (Fraunces variable serif with SOFT/WONK axes for display/titles, Figtree for text; bundled OFL fonts registered at launch via `registerBundledFonts`, silent fallback to New York / SF Rounded), `LunaMetrics`, and components (`lunaCard`, `LunaButtonStyle` `.lunaPrimary/.lunaSecondary/.lunaQuiet/.lunaDestructive`, `LunaPage`, `SectionTitle`, `LearnMore`, `Hint`, `Chip`, `LoadStatusView`, `WaveformView`, `MarkdownView`). `MainWindowController` is a plain `NSWindow` (resizable, frame autosaved as `LunaMainWindow`, transparent titlebar) hosting `MainView` (`NavigationSplitView`, sidebar + `MainPage`); `MainRouter` holds page, selected meeting and settings section. German display strings for languages and dates (`AppLanguage.displayName`, `Date.lunaDateTime`) regardless of system locale.

**Adding a refine backend:** implement `TextRefiner`, add a `RefinerKind` case (label, `huggingFaceID` or `nil`, availability), and map it in `RefinerManager.make`. Settings and AppState need no changes.

## Conventions

- Swift concurrency with `SWIFT_STRICT_CONCURRENCY: minimal`; UI-facing classes are `@MainActor`, progress callbacks are `@Sendable` and may arrive on any thread — hop to the main actor before touching published state.
- Everything user-facing lives in the menu-bar popover (`UI/MenuBarView`), the floating overlay (`UI/OverlayController`) and the main window (`UI/MainWindow`, `UI/Pages`, `Settings/Pages`). Build views only from `UI/Theme` tokens and components; check light and dark with `--ui-snapshot`. Meeting failures are additionally shown as an `NSAlert` because the popover is usually closed by then.
- Dependencies are SwiftPM packages declared in `project.yml` (FluidAudio, KeyboardShortcuts, mlx-swift-examples → products `MLXLLM` + `MLXLMCommon`); `Package.resolved` under the xcodeproj is regenerated, not hand-edited.
- Developer self-tests (`--meeting-selftest`, `--queue-selftest`, `--refine-selftest`, `--vocab-selftest`, `--learn-selftest`, `--summary-selftest`, `--ui-snapshot`) are the substitute for a test target: reproducible, log-only, exit on their own. Extend them rather than adding ad-hoc debug UI.
